# RGB-сегментация локальных возвышенностей

Скопируйте папку `elevation_segmentation` целиком в корень `Space_FIT`.
Команды ниже выполняются **из корня Space_FIT**, через `python -m`.
Существующие `train.py`, `model.py` и `datasets/` не изменяются и не импортируются.

## Что обучается

DeepLabV3+ / ResNet34 из `segmentation_models_pytorch`, один выходной канал
логитов. Энкодер первоначально использует ImageNet. Выход после sigmoid —
оценка вероятности класса «локальная возвышенность», после порога — маска 0/1.
Это отдельная модель; первая модель типов местности остаётся отдельной.

Проверена структура репозитория BondarchukAnton/Space_FIT на коммите
`228d6cfb5cd9d5d2971037fb6d2bb82698cf4332`. В корневом train.py сейчас используется
UnetPlusPlus / tu-maxvit_base_tf_512. Здесь выбран более лёгкий энкодер для
работы с окнами 512×512 при ограниченной видеопамяти. Превосходство по IoU
без реального обучения не утверждается. SMP позволяет заменить архитектуру
на Unet или UnetPlusPlus и выбрать другой совместимый энкодер в config.json.
Для новых архитектур создавайте отдельную папку эксперимента. Нормализация
normalization_mean/std в config.json задана для ImageNet ResNet; при выборе
другого семейства энкодеров сверьте его ожидаемые mean/std и обновите эти
поля при необходимости. Нормализация сохраняется в чекпоинте и используется
при инференсе автоматически.

Используются **только RGB и индексные маски**, DEM/TPI/flat не подаются модели.
TPI фактически определяет целевую разметку; его подача на вход давала бы
информацию, которой у алгоритма на RGB-инференсе не будет.

## Установка

Активируйте рабочее окружение проекта. Проверьте PyTorch с CUDA:

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
python -m pip install -r elevation_segmentation/requirements.txt
```

Текущий подходящий CUDA PyTorch можно оставить. Если его нет, установите
совместимые torch/torchvision по https://pytorch.org/get-started/locally/.
Для разных видеокарт могут требоваться разные сборки CUDA. CPU тоже поддерживается,
но полный прогон будет медленным. Модуль проверен с SMP 0.5.0; если в старом
окружении другая версия SMP и обновление нежелательно, создайте отдельное
окружение для этой модели.

Первый запуск с encoder_weights="imagenet" скачивает веса. Для работы без
интернета предварительно заполните кэш весов. Resume и инференс создают модель
с encoder_weights=None и **не скачивают ImageNet**. Значение null в config.json
означает обучение с нуля, а не автоматический переход при ошибке загрузки.

## Пути и проверка данных

В `elevation_segmentation/config.json` задайте `dataset_root` и `output_dir`.
Есть переопределения командной строки:

```bash
python -m elevation_segmentation.train \
  --data "/media/workerfit/SP PHD U3/ТГУ/Космос/elevation_dataset/dataset_250" \
  --output runs/elevation_resnet34_512 \
  --check-data
```

Проверяются все пары, размеры, значения масок, отсутствие полностью
исключённых изображений, повторов RGB между split и общих location_id.
Полный географический аудит пересечений не повторяется: его выполнял сборщик.
Читается manifest.jsonl; если его нет — train/images, train/masks, val/images,
val/masks. Результат — dataset_report.json. Отпечаток RGB/масок проверяется
при каждом resume: изменение датасета не принимается молча.

Из предоставленного описания: **217 train и 94 val**, а не 250 train.
Это не препятствует запуску; расширить набор можно позднее отдельным
экспериментом. Положительный класс занимает примерно 6.15% действительных
пикселей train и 9.94% val. Число файлов terrain не равно числу обучающих пар.

Маски читаются без перевода индексов в яркость: 0 — остальная местность,
1 — возвышенность, 255 — ignore. Padding маски в этом модуле тоже 255,
поскольку дополненные пиксели не имеют разметки. Реальный фон 0 обучается.

В описании есть две детали, которые не следует переносить буквально:
- уже готовые PNG 0..255 нельзя снова калибровать формулой raw*0.0001-0.1;
  код делит PNG на 255 и применяет нормализацию ImageNet;
- одна фиксированная CRS не предполагается: в названиях есть тайлы зон 44 и 45,
  а действительную CRS конкретного кадра определяют его метаданные. Для RGB-модели
  CRS не требуется, но исходный масштаб 10 м/пиксель требуется.

## Обучение

```bash
python -m elevation_segmentation.train \
  --data "/media/workerfit/SP PHD U3/ТГУ/Космос/elevation_dataset/dataset_250" \
  --output runs/elevation_resnet34_512
```

Начальные настройки: crop_size=512, batch_size=1, accumulation_steps=4,
60 эпох, два случайных окна каждого train-изображения за эпоху. Для 217 файлов
это 434 вырезки за эпоху; они не считаются новыми независимыми снимками.
Видеопамять проверяйте на своей видеокарте: гарантировать расход без прогона
на ней нельзя. Инференс использует tile_size=512 и overlap=128. Изменение размеров после
начала обучения требует нового эксперимента, а не resume прежнего.

Изображения не уменьшаются: 512 пикселей остаются 5.12 км. Аугментации:
повороты на 90°, отражение, небольшие изменения яркости и контраста.
Для изображения с положительными пикселями в половине случаев окно выбирается
так, чтобы содержать хотя бы один такой пиксель. Полностью фоновые изображения
тоже участвуют. Перевзвешенного sampler по группам нет.

Функция потерь:

`0.5 * BCEWithLogits(pos_weight=2) + 0.5 * Dice`.

Индекс 255 исключается из обеих составляющих. Умеренный вес 2 выбран вместе
с положительно ориентированными вырезками; полный обратный дисбаланс около
15 здесь не применяется автоматически. Это начальная настройка, которую
следует оценивать по precision/recall и IoU возвышенностей. Фон получает
градиенты BCE, в том числе на полностью фоновых вырезках.

Статистики BatchNorm фиксированы из-за batch_size=1; аффинные параметры
обучаются. Накопление градиентов не увеличивает батч для BatchNorm.
Используются AdamW, разные LR энкодера/декодера, AMP на CUDA, ограничение
нормы градиента, ReduceLROnPlateau по IoU возвышенностей.

Радиус 3000 м задаёт окрестность диаметром 6 км. Окно 512×512 при 10 м/пиксель
охватывает 5.12×5.12 км: полной окрестности этого радиуса модель не видит
даже для центрального пикселя. Перекрытие окон не добавляет контекст каждому
прямому проходу. Поэтому переход на 512 может снизить согласие с разметкой
на крупномасштабном рельефе; это нужно оценить по val. Модель приближает DEM-разметку, а не измеряет высоту в метрах.

## Валидация и результаты

Каждую эпоху проверяются все полные val-снимки без случайных вырезок и аугментаций.
Окна объединяются по вероятностям с весами, затем каждый исходный пиксель
учитывается один раз. 255 исключён. Подсчитывается общая матрица ошибок,
из неё IoU возвышенностей и фона, mIoU, precision, recall, Dice и accuracy.
Метрики групп mixed/background также записываются, если group есть в manifest.
Если знаменатель метрики нулевой, она записывается null, а не искусственным 1.

Выбор лучшей модели — **IoU класса возвышенностей**, порог по умолчанию 0.5.
Автоматического подбора порога на val нет. Если будете вручную подбирать
порог по val, учитывайте это при интерпретации итоговых метрик.

В output:
- last.pt — последнее сохранённое состояние обучения;
- best.pt — состояние после эпохи с лучшим IoU возвышенностей;
- config.json, dataset_report.json — параметры и проверка данных;
- history.jsonl, train.log — ход обучения;
- val_metrics.json — последние общие, групповые и покадровые метрики;
- previews/val_*.jpg — RGB | эталон (белый=1, пурпурный=255) | предсказание;
- tensorboard/ — скаляры: `tensorboard --logdir runs/elevation_resnet34_512/tensorboard`.

## Продолжение после прерывания

```bash
python -m elevation_segmentation.train \
  --data "/media/workerfit/SP PHD U3/ТГУ/Космос/elevation_dataset/dataset_250" \
  --output runs/elevation_resnet34_512 \
  --resume runs/elevation_resnet34_512/last.pt
```

Сохраняются веса, оптимизатор, scheduler, AMP scaler, генераторы случайных
чисел, эпоха, следующий батч, лучший IoU и накопленная статистика потерь.
last.pt обновляется каждые 25 шагов оптимизатора, перед val и после эпохи.
Можно уменьшить save_every_steps до начала эксперимента. При Ctrl+C/сбое
несохранённая часть работы повторяется с предыдущего чекпоинта. Чекпоинт
пишется через временный файл и атомарную замену.

Вырезки воспроизводимы по seed/эпохе/индексу и не зависят от числа workers.
Resume проверяет параметры и данные; менять epochs, batch_size, crop_size,
архитектуру или функцию потерь в нём нельзя. Пути, устройство и num_workers
можно менять. Побитовая эквивалентность проверена на CPU в синтетическом тесте;
разные GPU, версии библиотек и недетерминированные операции могут дать отличия.
Продолжение всегда выполняйте с тем же config, с которым запускали обучение.

## Начальные веса другого эксперимента

```bash
python -m elevation_segmentation.train \
  --config elevation_segmentation/config.json \
  --output runs/elevation_new \
  --init-from /path/to/previous_checkpoint.pt
```

Это новый эксперимент: оптимизатор и эпохи новые. Сначала загружается ImageNet
(если указан), затем совместимые по имени и форме тензоры. Старая голова
сегментации всегда исключается. Если нет совместимого энкодера — явная ошибка.
Чекпоинт MaxViT не совместим с ResNet34; случайно совпавшие тензоры не являются
основанием считать перенос выполненным. Для точного продолжения нашей бинарной
модели используйте --resume, включая её обученную голову.

## RGB → маска: команда

```bash
python -m elevation_segmentation.inference \
  --checkpoint runs/elevation_resnet34_512/best.pt \
  --image /path/to/rgb.png \
  --output prediction
```

Результат: mask.png (uint8 0/1), mask_preview.png (0/255 только для просмотра),
overlay.png и probability.npy (float32 H×W). Размер выходной маски совпадает
с входным изображением, включая Full HD. Никакой DEM для вызова не нужен.
Модель предсказывает 0/1 для всех пикселей: самостоятельно определять надёжность
и воспроизводить SCL-ignore она не обучалась. В маске предсказаний 255 не появляется.

## Использование в своём алгоритме

```python
import numpy as np
from PIL import Image
from elevation_segmentation.inference import ElevationPredictor

predictor = ElevationPredictor("runs/elevation_resnet34_512/best.pt", device="auto")
rgb = np.array(Image.open("rgb.png").convert("RGB"))
mask = predictor.predict(rgb)          # uint8 H×W; 0/1
probability = predictor.predict_proba(rgb)  # float32 H×W; отдельный прямой проход
```

Если нужны сразу оба результата, получите probability один раз и вычислите
`mask = (probability >= predictor.threshold).astype(np.uint8)`.
Отдельный исполняемый пример — example_usage.py:

```bash
python -m elevation_segmentation.example_usage \
  --checkpoint runs/elevation_resnet34_512/best.pt --image /path/to/rgb.png
```

При OpenCV сначала переводите BGR в RGB. Требуется согласованный масштаб
10 м/пиксель и близкая радиометрия: произвольный наклонный кадр камеры БВС
не эквивалентен обучающему спутниковому изображению.

## Изменение на 512×512

Обучение: вырезки 512×512 из исходных изображений, без изменения GSD.
Инференс: вход 512×512 даёт маску 512×512 за один проход. Более крупный
вход обрабатывается окнами 512×512 с перекрытием 128 и даёт маску исходного
размера. Меньший вход дополняется, затем результат обрезается до его размера.

Используется масштаб существующего датасета **10 метров на пиксель**.
**10 пикселей на метр = 0.1 метра на пиксель** — это другой масштаб с отличием
в 100 раз по каждой оси. Для него понадобятся соответствующие исходные
данные и пересмотр формирования датасета; растягивание Sentinel-2 не добавит
пространственных деталей. В этой версии такое растягивание не выполняется.

Если ранее обучение уже запускалось с окнами 1024, новый конфиг несовместим
с его --resume. Начните эксперимент в runs/elevation_resnet34_512.
Для использования общих весов прежней модели доступен --init-from; при этом
голова сегментации переинициализируется, как описано выше. Для инференса
старого чекпоинта явно задайте --tile-size 512 --overlap 128: иначе он
восстановит исходные параметры окон из своего чекпоинта. Новые чекпоинты
этой версии автоматически используют 512/128.

### Именование файлов

Формат имени: `{prefix}_dw_{lat}p{lon}-{YYYYMMDD}.tif`

- `prefix` — `label` (аннотация), `probs` (вероятности) или `s2` (изображение)
- `lat` — широта (знак кодируется: отрицательная — без префикса, положительная — с префиксом `p`)
- `lon` — долгота (аналогично)
- `YYYYMMDD` — дата съёмки

**Примеры:**
```
label_dw_-100p3728788374_22p1422143633-20190430.tif
probs_dw_-100p3728788374_22p1422143633-20190430.tif
s2_dw_-100p3728788374_22p1422143633-20190430_B02-B03-B04-B08.tif
```
→ широта ≈ −100.37°, долгота ≈ 22.14°, дата 2019-04-30

**Важно:** `label_`, `probs_` и `s2_` файлы с одинаковым именем (без префикса и суффикса каналов) описывают **один и тот же тайл** (одна и та же область, одна и та же дата).

### Рекомендации по отображению RGB-изображений

> ⚠️ **Важно:** данный раздел содержит **рекомендации** по визуализации, а не обязательные требования к работе с изображениями.
> Вы можете использовать любой удобный способ отображения — приведённые ниже подходы являются
> проверенными и корректными, но не единственно возможными.

Ниже описан подход, используемый в [`Untitled.ipynb`](Untitled.ipynb) для интерактивного просмотра тайлов.

|---|---|---|


#### 3. Растяжка динамического диапазона (stretch)

Значения в файлах — `uint16` (0–~22 000), что не подходит для прямого отображения в `imshow`
(ожидаемый диапазон 0–1). Рекомендуется **перцентильная растяжка**:

```python
def stretch_band(band: np.ndarray, p_low: float = 2.0, p_high: float = 98.0) -> np.ndarray:
    """Перцентильная растяжка валидных пикселей в диапазон [0, 1]."""
    valid = band[band > 0]          # исключаем нули (отсутствие данных)
    if valid.size == 0:
        return np.zeros_like(band, dtype=np.float32)
    v_min, v_max = np.percentile(valid, (p_low, p_high))
    if v_max <= v_min:
        v_max = v_min + 1e-5
    return np.clip((band - v_min) / (v_max - v_min), 0.0, 1.0)
```

**Почему именно так (рекомендации):**

- **Перцентили 2–98** — отбрасывают экстремальные значения (высокие облака, тёмные тени),
  чтобы основная масса пикселей была хорошо различима.
- **Фильтр `band > 0`** — исключает нулевые пиксели (4 файла полностью нулевые,
  см. раздел «Нулевые файлы»), чтобы они не искажали перцентили.
- **`np.clip(..., 0.0, 1.0)`** — гарантирует, что результат в диапазоне,
  ожидаемом `matplotlib.imshow` для `float32`.
- Альтернативные подходы (линейная растяжка по min/max, гамма-коррекция,
  логарифмическая растяжка) также допустимы — выбор зависит от задачи визуализации.

## Географическая привязка

- **CRS:** UTM-зоны WGS 84 (EPSG:326xx / EPSG:327xx), варьируется от тайла к тайлу
  - Северное полушарие: EPSG:32603–32658
  - Южное полушарие: EPSG:32717–32759
  - Всего 60+ различных UTM-зон
- **Transform:** `| 10.00, 0.00, X |` / `| 0.00, -10.00, Y |` / `| 0.00, 0.00, 1.00 |`
  - где X, Y — координаты верхнего левого угла тайла в метрах
- **Размер тайла в метрах:** 512 × 10 = **5120 м × 5120 м** (~5.12 км × 5.12 км)
- **CRS изображений S2** полностью совпадает с CRS соответствующих label/probs файлов (проверено для всех 409 пар)

## Скачивание исходных снимков Sentinel-2

Изображения в `s2_images/` были скачаны скриптом [`download_s2.py`](download_s2.py)
с [Copernicus Data Space Ecosystem](https://dataspace.copernicus.eu) по
`s2_system_index` из `meta.csv`.

### Подготовка

1. Зарегистрируйтесь на [dataspace.copernicus.eu](https://dataspace.copernicus.eu).
2. Создайте OAuth2-клиента (Client ID + Client Secret) в разделе **My Clients**.
3. Задайте переменные окружения:
   ```bash
   export CDSE_USERNAME="..."
   export CDSE_PASSWORD="..."
   ```

### Запуск

```bash
# Проверка: скачать 3 сцены (RGB + NIR, обрезанные к тайлам 512x512)
python3 download_s2.py --limit 3

# Все 409 сцен, каналы 10 м (B02, B03, B04, B08)
python3 download_s2.py

# Все 12 каналов L2A
python3 download_s2.py --bands B02 B03 B04 B08 B05 B06 B07 B08A B11 B12 B01 B09

# Без обрезки (полный MGRS-тайл 109x109 км)
python3 download_s2.py --no-crop
```

### Что делает скрипт

- Читает `dw_test_zenodo/meta.csv`, парсит `s2_system_index`
  (`<время съёмки>_<время обработки>_<MGRS-тайл>`).
- Находит продукт `S2MSI2A` в каталоге CDSE и скачивает zip-архив
  (кэш в `s2_cache/`, поддержка resume).
- Извлекает выбранные каналы, **обрезает к границам тайла** (512×512 px,
  10 м/px) по географическим координатам из соответствующего `label_*.tif`.
- При несовпадении UTM-зон выполняет автоматическую перепроекцию (bilinear).
- Сохраняет результат в `s2_images/s2_<имя тайла>_<каналы>.tif` (GeoTIFF, deflate).
- Идемпотентен: уже обработанные сцены пропускаются при повторном запуске.

## Важные замечания

1. **NaN в probs:** ~5% пикселей содержат `NaN` во всех 9 каналах одновременно. При расчёте метрик или обучении моделей необходимо обрабатывать эти пиксели (маскировать или исключать).
2. **Канал 9 в probs:** его точный смысл не подтверждён. Не является ни argmax, ни max, ни sum, ни mean по каналам 1–8. Вероятно, вероятность класса `snow_and_ice` (индекс 8) или дополнительная метрика модели.
3. **Канал 2 в label:** содержит ground truth. В выборке не встречены классы 4 (`crops`) и 8 (`snow_and_ice`), но диапазон по документации — 0–8.
4. **CRS не одинаков** для всех тайлов — при работе с несколькими тайлами одновременно необходимо учитывать разные UTM-зоны (60+ зон).
5. **Соответствие label ↔ probs ↔ s2:** файлы с одинаковым именем (без префикса) описывают один и тот же тайл. `label_ch1` (предсказание) = `argmax(probs_ch1..ch8)`.
6. **4 нулевых файла S2:** 4 изображения полностью заполнены нулями (см. таблицу выше). Их следует исключать из датасета.
7. **Значения S2 — reflectance ×10 000:** тип `uint16`, значения 0–~22 000. Для нормализации делить на 10 000 (получается reflectance 0–2.2) или на 2 500 (стандартная нормализация S2).
8. **Нет метаданных каналов в TIF:** описания каналов (B02, B03, B04, B08) не записаны в GeoTIFF — порядок каналов соответствует порядку в имени файла (`_B02-B03-B04-B08`).

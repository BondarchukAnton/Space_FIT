**Инструкции для ИИ-агентов по работе над проектом Space_FIT**  
Данный документ содержит инструкции и правила, обязательные к исполнению всеми ИИ-агентами, работающими над проектом сегментации типов местности на базе аэроснимков.  
**1. Обзор проекта**  
- **Назначение**: семантическая сегментация оптических аэроснимков.   
- **Архитектура**: DeepLabV3+ с энкодером EfficientNet-B3 (с использованием библиотеки segmentation_models_pytorch) либо лучши по точности вариант.  
**2. Структура проекта**  
Проект имеет следующую структуру модулей и зависимостей:  
- dataset — реализация torch.utils.data.Dataset для загрузки изображений и масок, ремаппинга классов и применения аугментаций. Импортирует config.py.  
- model.py — инициализация архитектуры нейронной сети.
- utils.py — вспомогательные функции (настройка логирования, метрики, визуализация).  
- train.py — скрипт обучения модели. Реализует цикл обучения, валидации, логирование в TensorBoard и сохранение чекпоинтов. Импортирует dataset.py, model.py, utils.py.  
- inference.py / test.py — скрипты для инференса и тестирования обученной модели. Импортируют model.py, dataset.py, utils.py.  
**Порядок работы**: dataset -> model -> train -> test/inference.  
**3. Правила оформления комментариев**  
- **Язык**: русский. Следует использовать устоявшуюся научную терминологию Российской Федерации в области обработки изображений, дистанционного зондирования Земли и машинного обучения.  
- **Стиль**: профессиональный, лаконичный, точный.  
- **Формат docstring**: Google-стиль (Args, Returns, Raises).  
- **Запрет на**: эмодзи, значки, жаргон, разговорные обороты.  
- **Запрещённые слова/обороты (типичные для языковых моделей)**:  
  - критичный, критический, ключевой  
  - важно отметить, стоит отметить, следует отметить  
  - необходимо подчеркнуть  
  - имплементация (вместо — реализация)  
  - нетривиальный  
  - лучшие практики (вместо — рекомендованные подходы)  
  - на лету (вместо — в процессе выполнения, динамически)  
  - из коробки (вместо — без дополнительной настройки)  
  - под капотом (вместо — внутренняя реализация)  
  - и т.д.  
- **Рекомендованная терминология**:  
  - обучающая выборка, валидационная выборка, тестовая выборка  
  - функция потерь (не лосс)  
  - скорость обучения (не learning rate в комментариях)  
  - эпоха, батч, прямой проход, обратное распространение  
  - матрица ошибок (не confusion matrix в комментариях)  
  - точность пересечения-объединения (IoU)  
  - сегментационная маска, пиксельная разметка  
  - энкодер, декодер (допустимые заимствования)  
  - чекпоинт (допустимое заимствование)  
**4. Правила вывода в консоль и логи**  
- Использовать модуль logging, не print (исключение — прогресс-бары библиотеки tqdm).  
- **Формат**: [ГГГГ-ММ-ДД ЧЧ:ММ:СС] УРОВЕНЬ модуль — сообщение.  
- **Уровни**:  
  - DEBUG — отладочная информация;  
  - INFO — ход выполнения, результаты;  
  - WARNING — нештатные ситуации;  
  - ERROR — ошибки.  
- **Стиль сообщений**: профессиональный, без восклицательных знаков, без слов-паразитов.  
- **Примеры**:  
  - **Правильно**: "Модель загружена: DeepLabV3+ / efficientnet-b3, 12.4M параметров."  
  - **Правильно**: "Эпоха 15/50: train_loss=0.342, val_loss=0.401, mIoU=0.548."  
  - **Неправильно**: "Модель успешно загружена! Ключевой шаг выполнен."  
  - **Неправильно**: "Критически важная метрика mIoU составила 0.548."  
**5. Правила именования**  
- Переменные и функции: snake_case.  
- Классы: PascalCase.  
- Константы: UPPER_SNAKE_CASE.  
- Файлы модулей: snake_case.py.  
- Следует использовать осмысленные имена без сокращений. Допустимые общепринятые сокращения: lr, cfg, img, msk, gt.  
**6. Порядок работы с проектом**  
1. Установить зависимости: pip install -r requirements.txt  
2. Указать пути к датасету.  
3. Выбрать классы для обучения: переменная SELECTED_CLASSES.  
4. Запустить обучение: python train.py [--args]  
5. Мониторинг процесса: tensorboard --logdir runs  
6. Тестирование модели: python test.py --image <path> --checkpoint <path>  
7. Встраивание в сторонний код: from inference import SegmentationModel  
**7. Архитектурные решения**  
- **Ремаппинг классов**: оригинальные пиксельные значения преобразуются в непрерывные индексы.  
- Невыбранные для обучения классы объединяются в общий фон (индекс 0).  
- Применяется комбинированная функция потерь (Cross-Entropy + Dice) для компенсации дисбаланса классов.  
- Используется автоматическая смешанная точность (AMP — Automatic Mixed Precision) для экономии памяти видеокарты.
